# Phase 1: workspace and goatbeat-core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A uv workspace with CI and the framework-agnostic `goatbeat-core` package: domain types, interval and cron triggers with DST rules, misfire planning, typed registry, memory and SQLite stores with leases and fenced claims, and a scheduler loop.

**Architecture:** Namespace packages like goatseo: the `goatbeat` facade owns `goatbeat/__init__.py`, `goatbeat-core` provides `goatbeat.core`. The scheduler depends only on protocols (`ScheduleStore`, `LeaseManager`, `TaskSubmitter`, `Clock`, `MetricsSink`), so phase 2 adds PostgreSQL by implementing the same protocols and passing the same conformance suite.

**Tech Stack:** Python 3.13+, stdlib only at runtime (`zoneinfo`, `sqlite3`, `logging`, `threading`), uv workspace, pyright strict, ruff, pytest, hypothesis, croniter (dev only), lefthook.

**Spec:** `docs/superpowers/specs/2026-09-25-goatbeat-design.md`

## Global Constraints

- `requires-python = ">=3.13"`; ruff `target-version = "py313"`; pyright `pythonVersion = "3.13"`, strict.
- `goatbeat.core` imports nothing outside the stdlib at runtime.
- Every datetime inside core is aware and UTC (`Instant`); naive input raises `NaiveDatetimeError`.
- No `Any` outside documented boundaries; no module-level mutable state.
- English everywhere in the repository; no em dashes; comments at most two lines, only for a why.
- Conventional single-line commits, no Claude or Anthropic reference.
- Actions pinned by commit hash (reuse goatseo pins).

## Review Focus

1. Cron evaluated across DST transitions: fixed-hour jobs run once, wildcard-hour jobs follow real time. Test in `test_cron_trigger.py` for America/New_York, Europe/Paris and Australia/Lord_Howe.
2. A scheduler whose lease was taken over must not claim anything (stale fencing token). Test in the conformance suite.
3. A crash between claim and submission must lead to re-submission with the same idempotency key. Test in `test_scheduler.py`.
4. Long outages must not explode (`catch_up` capped by `max_catch_up`, `run_once` dispatches one). Test in `test_misfire.py`.
5. Unsatisfiable cron (`0 0 30 2 *`) must fail at parse time, not loop forever. Test in `test_cron_expression.py`.

### Task 5: Cron trigger with DST

**Produces:** `CronTrigger(expression: CronExpression, timezone: ZoneInfo)`, `.next_after(i: Instant) -> Instant`.

Algorithm: iterate matching naive wall times starting two hours before the local wall time of `i`. For each wall time `w`:
- nonexistent (utc of fold 0 != utc of fold 1 and round trip fails): fixed hour yields the transition instant (found by bisection between the two candidate UTC instants); wildcard hour yields nothing;
- ambiguous: fixed hour yields fold 0 only; wildcard hour yields fold 0 and fold 1;
- otherwise its single instant.
Keep candidates strictly after `i`; once a candidate exists, scan a further three hours of wall time and return the minimum.

- [ ] Tests (New York 2026-03-08 and 2026-11-01, Paris, Lord Howe 30-minute shift, UTC, midnight boundaries): `30 2 * * *` gives 03:00 EDT on spring day; `30 1 * * *` gives one run on fall day; `*/30 * * * *` gives both 01:00 and 01:30 twice on fall day and skips 02:xx in spring; results strictly increasing over a year (hypothesis).
- [ ] Implement, commit `feat(core): add timezone-aware cron trigger`.

### Task 8: Execution types, protocols, memory store, conformance

**Produces:**
```python
class LeaseManager(Protocol):
    def acquire(self, holder: SchedulerId, ttl: timedelta) -> Lease | None: ...
    def release(self, lease: Lease) -> None: ...

class ScheduleStore(Protocol):
    def sync_code_schedules(self, schedules: Sequence[Schedule], now: Instant) -> None: ...
    def save_schedule(self, schedule: Schedule, now: Instant) -> Schedule: ...
    def get_schedule(self, name: str) -> Schedule | None: ...
    def list_schedules(self) -> Sequence[Schedule]: ...
    def set_enabled(self, name: str, enabled: bool, now: Instant) -> None: ...
    def due_schedules(self, now: Instant, limit: int) -> Sequence[Schedule]: ...
    def claim(self, lease: Lease, schedule: Schedule, plan: OccurrencePlan, now: Instant) -> Sequence[Execution]: ...
    def claim_manual(self, lease: Lease, schedule: Schedule, key: IdempotencyKey, now: Instant) -> Execution: ...
    def pending_submissions(self, now: Instant, stale_before: Instant, limit: int) -> Sequence[PendingSubmission]: ...
    def mark_dispatched(self, key: IdempotencyKey, at: Instant, receipt: SubmissionReceipt) -> None: ...
    def mark_submit_failed(self, key: IdempotencyKey, error: str, retry_at: Instant | None) -> None: ...
    def next_wakeup(self) -> Instant | None: ...
    def recent_executions(self, schedule_id: ScheduleId | None, limit: int) -> Sequence[Execution]: ...
    def wait_for_change(self, timeout: timedelta) -> bool: ...
```
`claim` raises `LeaseLostError` when the fence fails, inserts claims with `ON CONFLICT DO NOTHING` semantics and advances `next_run_at`. `StoreConformance` is a base class with `make_store()` / `make_leases()` hooks and `test_*` methods.

- [ ] Conformance tests: lease acquire, renew keeps token, takeover after expiry increments token, stale token claim raises `LeaseLostError`, duplicate claim yields one execution, due query ordering and limit, disabled excluded, pending includes stale `claimed` and due `submit_failed`, `mark_submit_failed(retry_at=None)` sets `failed`, code sync disables removed schedules, `next_wakeup`.
- [ ] Implement `MemoryStore` (one `threading.Lock`, lease time from the injected `Clock`), commit `feat(core): add store protocols and in-memory store`.
